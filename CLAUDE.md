# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

Or Litany's personal academic homepage, served as a static site via GitHub Pages (`orlitany.github.io`). It also contains Python tooling that generates a LaTeX CV (`latex/cv.pdf`) from the same JSON data that feeds the website, so the site and the CV stay in sync.

There is no build step, bundler, or framework for the site itself — it's a single `index.html` that loads Vue 2 (via CDN) and jQuery, then fetches JSON data files client-side.

## Running locally

The site must be served over HTTP (not opened as a `file://` URL) because it fetches JSON via `$.getJSON`/AJAX:

```
python3 -m http.server 8000
# or
http-server
```

Then visit `http://localhost:8000/`.

## Generating the CV PDF

```
python3 generate_cv.py
```

This reads `cv_files/publications.json`, `cv_files/workshops.json`, and `cv_files/students.json`, regenerates `latex/publications.tex`, `latex/workshops.tex`, and `latex/advising.tex`, then compiles `latex/cv.tex` with `tectonic` (must be installed and on `PATH`) to produce `latex/cv.pdf`. Bio/education/experience sections of `cv.tex` are static and not regenerated by this script.

There is a separate, gitignored `local_internal_cv/` directory with `generate_cv_internal.py` for a private Technion-only CV variant — bootstrap it with `--init` from `latex/`. Do not un-gitignore this directory.

## Architecture

**Data flow:** All dynamic content on the page (publications, talks, workshops, press, news, courses, students, bibtex citations) lives in JSON files under `cv_files/`. `helper_functions/load_dicts_from_json.js` defines the Vue instance mounted at `#vue-app` in `index.html`, and on load fetches each JSON file independently via jQuery AJAX, populating the Vue instance's `data`. `citations.bib` is parsed client-side by a hand-rolled BibTeX parser in that same file (falls back to `cv_files/bibs.json` if the `.bib` fetch fails).

**Editing site content:** To add/change a publication, talk, workshop, press mention, news item, course, or student, edit the corresponding JSON file in `cv_files/` — never hand-edit generated HTML, since the page renders these lists via Vue templates in `index.html`.

**Show-more pagination:** Each section (workshops, talks, publications, press) has an independent expand/collapse state in `expandedSections`, with per-section initial-item counts configured in `INITIAL_ITEMS_TO_SHOW` at the top of `load_dicts_from_json.js`. News uses a separate incremental "show more" (`newsToShow` / `NEWS_ITEMS_PER_PAGE`).

**CV generation reuses the site's data:** `generate_cv.py` transforms the same `cv_files/*.json` into LaTeX fragments included by `latex/cv.tex`. When changing the shape of a JSON file (e.g. adding a field to a publication or student entry), check both the Vue rendering in `index.html`/`load_dicts_from_json.js` and `generate_cv.py`, since they parse the same JSON independently and will silently ignore fields the other doesn't know about. Note `latex/talks.tex` is `\input` by `cv.tex` but has no generator counterpart in `generate_cv.py` — it's hand-maintained and can drift out of sync with `cv_files/talks.json`.

**Styling:** `OL_files/style_new.css` is the only stylesheet; it's the one `index.html` links.

**`helper_functions/`** also contains a legacy notebook (`json_to_latex.ipynb`, `pdf_downloader.ipynb`) not part of the regular generation flow, plus `fetch_patents.py` which scrapes Google Patents to produce `cv_files/patents.json` (not currently wired into `index.html`).

## Notes

- `example_cv.json` is a template/reference schema, not live data.
- `notes.txt`, `read_json.ipynb`, and `publications_backup.js` are gitignored scratch files if present locally.
- SEO/social metadata (Open Graph, Twitter cards, JSON-LD `Person` schema) is hardcoded at the top of `index.html` — update it there if bio facts (title, affiliation, awards) change, since it's duplicated from the bio text in the page body.
